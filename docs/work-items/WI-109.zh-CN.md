# WI-109——生命周期串行顺序契约

## 目标

当治理步骤被跳过或重复时，让 Work Item 生命周期 fail closed。Runtime 记录带有
preflight 决策和 snapshot 绑定的 receipt，在 verification/finish 前要求一次
checkpoint，并在转换不能继续时保留 active 状态。

## 范围

- 在 repository lifecycle service 中执行有序转换；
- 让 CLI 与 MCP 使用相同的 repository-local preflight receipt；
- 拒绝重复 checkpoint 以及乱序的 finish/archive/close；
- 无条件保留 verification evidence 完整性检查；
- 增加负向和恢复回归测试；
- 在三种面向读者的语言文档中说明生命周期契约。

## 边界

不新增审批规则，不改变 Contract 含义，不重写历史 Work Item，也不编辑全局 Agent/MCP
配置。若 yellow 仅仅因为下一生命周期步骤将要收集的 evidence 尚不存在，可以执行
checkpoint；但 finish 仍要求 verification 后的决策为 green。

## 验收

1. `start → verify → finish` 在没有 preflight 和一次 checkpoint 时不能完成。
2. red preflight 不能执行 checkpoint；重复 checkpoint 失败且不改变 summary。
3. verification 针对最终 snapshot 刷新 preflight 绑定，合法 Work Item 可以按顺序
   finish、archive、close。
4. 即使 `requiredEvidenceClasses` 为空，finish/archive/close 也拒绝被篡改的
   verification evidence。
5. 转换失败时保留 active 记录，支持恢复。
6. CLI 与 MCP 使用相同的 repository-local preflight 语义。

## 验证

- `cargo test --locked -p cockpit-repository --all-targets --all-features -- --test-threads=1`
- `cargo test --locked -p cockpit-cli --all-targets --all-features -- --test-threads=1`
- 合并前执行 workspace fmt、clippy 和完整测试 gate。
