# WI-33 — Cross-Process Evidence Reuse Integration

## Intent and Goal

Connect the accepted WI-32 reuse core to a calibrated Project Profile, an
atomic content-addressed receipt store, and one shared CLI/MCP verification
service so safe reuse survives process exit.

## Scope and Out of Scope

In scope: profile-authorized reusable commands, complete repository context,
schema evolution, bounded output identity, immutable receipts plus atomic
index, two-process CLI/MCP parity, invalidation, and cost telemetry.

Out of scope: attaching this repository, hosted provider attestation, profile
redesign, commit/push, hosted CI, signing, publication, and release.

## Sources and Unknowns

Sources: accepted WI-32; execution specification sections 13–16 and 22–24;
Repository Protocol v1; confirmed Project Profile behavior; current snapshot,
repository, CLI, and MCP code; locked V1 evidence-reuse references at commit
`e5acb677da6621004d96f0ef353c58fe8d3acfbf`.

Known: no production path currently loads or writes reusable receipts; all
CLI/MCP project commands execute under a protected policy.

Unknowns: hosted runner/provider attestation and long-term receipt retention
belong to later Work Items. No Unknown blocks the local cross-process design.

## Acceptance Criteria

1. Only exact `verified` commands in a `calibrated` profile are reusable.
2. One immutable pre-run authorization read derives the complete profile-bound
   context; post-run snapshots and raw identity rechecks cannot authorize new
   content.
3. Receipt/index storage is content addressed, strict, atomic, and path safe.
4. First successful run persists evidence; an unchanged second process reuses
   with zero process spawn.
5. Every identity change and every missing/untrusted store state executes.
6. Failed commands create no passed receipt; output identity is bounded.
7. Protected commands execute on every run and skipped count stays zero.
8. CLI and MCP consume one service and expose equivalent node/metric evidence.
9. Historical receipt directories are not scanned during normal verification.
10. This Work Item creates no `.ai/` state in the development repository.
