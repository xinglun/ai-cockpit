# WI-28 — Snapshot 派生治理信号

## 意图与目标

移除三个硬编码安全治理输入，从单个不可变 Snapshot 派生 repository input trust、
test weakening 和 coverage weakening。

## 范围与非范围

范围内：进程内有界 change facts、确定性信号分析、中央决策接线、CLI/MCP/生命周期
回归以及信息泄露测试。范围外：复制 V1、第二次 Git 扫描、通用语义代码分析、
外部 provider evidence、扩展 evidence class、安装自治理、发布及无关 Observer 能力。

## 来源与未知项

来源：用户执行指示第 10、13、15、24、25 节；WI-27 可执行 Oracle；当前
RepositorySnapshot 与中央 decision adapter。

已知：adapter 当前传入三个字面量 `false`，Snapshot 没有可复用的 change-line facts。
未知：设计之外的语言特定 weakening；不支持的检查必须保持明确 Unknown。

## 验收标准

1. 三个生产治理输入由 Snapshot 派生。
2. 每次决策只观察一次 Git，并保持四次 Git 调用。
3. 删除测试为红灯；降低 coverage 和 prompt injection 为黄灯。
4. 无法检查的相关变更为 Unknown/黄灯。
5. CLI/MCP 不序列化原始 source/diff text。
6. CLI、MCP、finish、archive、close 共享中央结果。

## 所需证据

聚焦 RED/GREEN、两轮 workspace、Clippy、fmt、diff、workflow、多语言与可执行
V1 Oracle 检查。

  `e5acb677da6621004d96f0ef353c58fe8d3acfbf` 上，十四个案例全部通过。
