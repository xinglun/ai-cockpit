# WI-26 — Deterministic MCP Security Test Fixtures

## Intent and Goal

Remove the temporary-directory race exposed during WI-25 reacceptance so the
workspace quality gate is deterministic under Rust's parallel test execution.

## Scope and Out of Scope

In scope: the MCP security test repository-name generator and its verification
evidence.

Out of scope: production MCP behavior, repository protocol behavior, V1 Oracle
integration, self-governance, release publication, and unrelated test helpers.

## Sources and Unknowns

Sources: the first reacceptance `cargo test --workspace` failure at
`crates/cockpit-mcp/tests/security.rs:16`, followed by a passing isolated rerun.

Known: two tests in one process can obtain the same process ID and nanosecond
timestamp, causing `create_dir` to fail with `AlreadyExists`.

Unknowns: none within this bounded fixture correction.

## Acceptance Criteria

1. Parallel MCP security tests cannot select the same temporary repository path.
2. No production crate behavior changes.
3. Repeated MCP security tests and two complete workspace test runs pass.
4. Clippy, formatting, and diff checks pass.

## Required Evidence

- RED: recorded `AlreadyExists` failure from the first full reacceptance run.
- Repeated `cargo test -p cockpit-mcp --test security` runs.
- Two `cargo test --workspace` runs.
- Clippy, fmt, and diff checks.
