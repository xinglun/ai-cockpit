# WI-32 — Fail-Closed Evidence Reuse Planner

## 意图与目标

用复合 receipt 校验、依赖感知计划和可观察的 bounded execution，替代调用方自行声明的
verification skip。

## 范围与非范围

范围内：content/diff/environment 复合身份、content-addressed passed receipt、
Fresh/Stale/Unknown 分类、真实 command identity、protected-node 强制、依赖失效及执行
metrics。

范围外：receipt 文件持久化、profile 驱动的 CLI/MCP reuse、repository attach、
commit/push、托管 CI、release 签名与发布。

## 来源与未知项

来源：用户授权的 WI-32 设计；执行指示第 14 节；当前 Rust evidence/executor 实现；
锁定提交 `e5acb677da6621004d96f0ef353c58fe8d3acfbf` 中的 V1 verification evidence
reuse 参考。

已知：当前 executor 可仅凭 `reuse: bool` 跳过 process，且 diff/environment 值未被
独立校验。

未知：repository receipt 位置、保留策略、profile allowlist 与 CLI/MCP 跨进程生命
周期属于下一集成 WI。本地进程内安全边界无阻断 Unknown。

## 验收标准

1. Receipt 绑定 passed result、node、output、时间戳及全部 content、diff、environment、
   command、scope、governance、toolchain、policy、stage、runner 身份。
2. 仅精确、passed、未过期、有效且非 protected 的 receipt 可复用。
3. 缺失/畸形/篡改/失败/未来/错误 node evidence 为 Unknown 并执行；当前 binding
   不匹配或过期为 Stale 并执行。
4. 真实 program 与 arguments 决定 command identity。
5. Protected node 始终执行，`protectedNodesSkipped` 保持零。
6. 任一 dependency 重跑会强制 downstream 执行。
7. Reused command 不创建 process；telemetry 报告 reuse 与 rerun 状态。
8. 生产代码不再保留 `reuse: bool` 或 `with_reuse(bool)` 跳过 API。
9. 本 WI 不创建 repository `.ai/` state。

## 验证

- RED：复合 receipt 测试因缺少 context、receipt、state 与 reason API 而无法编译。
- RED：typed candidate/planner 测试无法编译，executor 当时仍暴露 `with_reuse(bool)`。
- RED：CLI 输出缺少 stale/unknown/protected/planning metrics。
- RED：downstream process 会在 dependency 完成前启动；dependency-ready scheduler 使确定性
  顺序测试变绿，同时双进程 rendezvous 测试证明独立节点仍保持并行。
- RED：serde 接受未知 receipt 字段；严格 schema 反序列化现会拒绝。
- GREEN：6 个 evidence 测试与 11 个 execution 测试覆盖精确 reuse、每个 binding 变化、
  缺失/无效/失败/未来/过期 receipt、typed Protected/Reusable/NeverReuse policy、最终
  program 与 argument identity、dependency 失效/顺序、独立并行及 spawn failure。
- 真实调用次数证明：Fresh receipt 使真实 `false` command 在零 process 下报告 passed；
  stale/protected/dependency 情况会执行并失败。
- Mutation 证据：禁用 context mismatch 后 content mutation 被误报为 Fresh，测试失败；
  恢复后重新变绿。
- Review 证据：dependency ordering、strict deserialization、typed protected policy、逐节点
  audit result、spawn accounting 与 argument coverage 问题均在验收前修复。
- GREEN：两次全新的独立 `cargo test --workspace --quiet`。
- GREEN：拒绝 warning 的 Clippy、rustfmt、`git diff --check`、workflow YAML、Python
  编译、三语对应、旧 reuse/protected bool builder 为零、`.ai/` 不存在及锁定 V1 Oracle。
