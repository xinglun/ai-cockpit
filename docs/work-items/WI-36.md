# WI-36 — Release Gate Correction: Tag Identity and Runner Lifecycle

## Intent and Goal

Correct the two deterministic release blockers found during WI-35 pre-release
acceptance, then produce a new clean candidate that can be independently bound
to an immutable tag and current hosted runners. This Work Item does not publish
the Release or mutate the Homebrew tap.

## Scope and Out of Scope

In scope: peel annotated tags before comparing remote tag identity with the
release commit; add an annotated-tag regression fixture; migrate the ARM64
macOS build identity from deprecated `macos-14` to the supported fixed runner;
update manifest mappings, fixtures, tests, design/plan text, and release policy;
rerun local gates; and prepare a reviewable candidate diff. Commit/push is an
authorized integration handoff, not part of this local corrective step.

Out of scope: creating tags, publishing GitHub Releases, creating or modifying
`xinglun/homebrew-tap`, hosted dispatch, public installation, runtime governance
semantics, V1 installation, `.ai/` creation, or changing `cockpit.toml` to JSON.

## Sources and Unknowns

Sources: WI-35 pre-release acceptance; `.github/workflows/release.yml`; the
`cockpit-release` manifest validator and tests; the isolated annotated-tag
reproduction; official GitHub runner image availability; and the WI-35 design,
plan, and installation contract.

Known: an annotated tag's unpeeled object SHA differs from its peeled commit
SHA; the current publish job compares the unpeeled value; `macos-14` is in the
GitHub deprecation window; local Rust, release-contract, V1 Oracle, archive, and
Cargo Git checks are green; and the current candidate tree is not clean.

Unknowns that remain owned by WI-35: hosted job results, final tag and provider
Release identity, provenance attestations, tap permissions, tap PR identity, and
real adopter installation receipts.

## Acceptance Criteria

1. The publish job compares the remote tag's peeled commit (`refs/tags/<tag>^{}`
   or an equivalent verified lookup) with the manifest and workflow commit, and
   accepts the documented tag form without weakening immutability checks.
2. A regression test proves an annotated tag object SHA is rejected as a commit
   identity and its peeled commit is accepted; lightweight-tag behavior is
   explicitly covered or deliberately rejected.
3. The five-target manifest, workflow matrix, fixtures, tests, and docs use a
   currently supported fixed ARM64 macOS runner; no deprecated `macos-14` build
   identity remains.
4. `cargo fmt`, warnings-denied Clippy, two complete workspace test runs,
   Windows cross-target check, release workflow policy, YAML/Bash/Action pin
   checks, release-package tests, V1 Oracle, archive inspection, and Cargo Git
   installation pass from the corrected tree.
5. The corrected candidate diff is reviewable from the recorded base. The
   shared worktree intentionally remains uncommitted under the no-commit
   constraint; creating the integration commit and pushing it are handoff
   actions for the authorized WI-35/integration step.
6. No tag, provider Release, tap, PR, hosted dispatch, public installation, V1
   file, `.ai/` directory, or configuration-format migration is created by this
   Work Item.
