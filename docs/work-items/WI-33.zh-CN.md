# WI-33 — 跨进程 Evidence Reuse 集成

## 意图与目标

把已验收的 WI-32 reuse core 接到 calibrated Project Profile、原子 content-addressed
receipt store 与一个 CLI/MCP 共用 verification service，使安全复用可以跨进程存在。

## 范围与非范围

范围内：profile 授权 reusable command、完整 repository context、schema 演进、bounded
output identity、immutable receipt 与 atomic index、双进程 CLI/MCP parity、失效与成本
telemetry。

范围外：attach 当前仓库、托管 provider attestation、profile 重设计、commit/push、托管
CI、签名、发布与 release。

## 来源与未知项

来源：已验收 WI-32；执行指示第 13–16、22–24 节；Repository Protocol v1；已确认的
Project Profile 行为；当前 snapshot/repository/CLI/MCP 代码；锁定提交
`e5acb677da6621004d96f0ef353c58fe8d3acfbf` 的 V1 evidence-reuse 参考。

已知：当前没有 production 路径读取或写入 reusable receipt；全部 CLI/MCP project
command 都以 protected policy 执行。

未知：托管 runner/provider attestation 与长期 receipt retention 属于后续 WI。本地跨进程
设计无阻断 Unknown。

## 验收标准

1. 只有 `calibrated` profile 中精确 `verified` command 可复用。
2. 一次不可变的运行前授权读取派生完整且绑定 profile 的 context；运行后 snapshot 与
   原始 identity 复核不能用新内容重新授权。
3. Receipt/index store 必须 content-addressed、严格、原子且路径安全。
4. 首次成功运行持久化 evidence；未变化的第二进程以零 process spawn 复用。
5. 任一 identity 变化和任一缺失/不可信 store 状态都会执行。
6. 失败 command 不创建 passed receipt；output identity 有界。
7. Protected command 每次均执行，skipped count 保持零。
8. CLI 与 MCP 使用同一 service 并暴露等价 node/metric evidence。
9. 普通 verification 不扫描历史 receipt 目录。
10. 本 WI 不在开发仓库创建 `.ai/` state。
