# WI-30 — 自治理切换就绪

## 意图与目标

以真实、失败关闭的方式，准备从 Markdown Bootstrap 治理切换到由本仓库自己的 Rust
AI Cockpit runtime 治理。

## 范围与非范围

范围内：切换前置条件、精确 binary 身份、明确的 attach/profile 人类决策、轻量 `.ai/`
状态验证、doctor/status 检查以及首个受治理生命周期演练。

范围外：安装 V1、向仓库复制 runtime 或 schema、在脏 worktree 上静默 attach、未经
人类授权的 commit/push、托管 CI、tag、release 及无关功能。

## 来源与未知项

来源：用户明确当前尚未安装 AI Cockpit；产品规范第 3–5 节；
`docs/work-items/README.md`；Repository Protocol v1；已实现的 Rust attach、status、
doctor 和生命周期命令。

已知：当前不存在 `.ai/`，所以现有 WI 是手工 Bootstrap 记录。Rust attach 设计上只写
protocol facts。

未知：用于切换的已集成修订，以及 commit/integration、repository attach、profile
确认的人类权限。这些保持明确停止条件。

## 验收标准

1. attach 前，WI-25 至 WI-29 已审阅并集成到一个干净且明确的修订。
2. 记录精确 runtime binary 版本与 SHA-256 digest。
3. attach 与 profile 确认之前均有明确人类批准。
4. attach 只创建 `.ai/` facts，不复制 runtime 实现。
5. status 与 doctor 确认 protocol 兼容且仓库内无 runtime 代码。
6. 首个受治理生命周期演练证明中央 preflight 和 human close 路径后，才退役 Bootstrap。
7. 仅在全部切换证据为绿灯后修改 Bootstrap 文档。

## 所需证据

干净修订、完整本地门禁、可执行 V1 Oracle、binary digest、attach diff、status/doctor
receipt、人类 profile 决策与首个受治理生命周期 receipt。
