# WI-39 — 明示的 Agent Discovery / Adapter 層

## 意図と目標

ガバナンス上の決定を導入せず、明示的・検証可能・復旧可能な Agent Discovery /
Adapter 層を導入します。Runtime のインストール、repository attach、discovery、
接続、コンプライアンスは別々の状態として扱います。

## 範囲と対象外

範囲：provider-neutral adapter contract、canonical manifest/version 処理、provider
検出と明示的な install plan、repository-local ownership record、fail-closed な
doctor/repair/detach、標準 state/exit code、CLI-first 動作、三言語ドキュメント。

対象外：`attach` 中の自動 provider 注入、global MCP/home 設定、Agent prompt を
ガバナンス authority とすること、自動 Work Item 決定、public Release/Homebrew
変更、`--force` detach shortcut。

## ハード制約

- すべての操作は明示的な `--repo` を要求し、Core は global current project を持たない。
- `attach` は Layer 2 のままで、Agent host file を変更しない。
- `.ai/agent-interface.json` は discovery fact だけを保持し、unknown field と incompatible version は fail closed にする。
- `agent install` だけを Adapter の通常の write entry point とする。
- Managed content は repository-local digest record が所有し、無関係な user content を保持する。
- Managed section の変更や曖昧さがあれば `detach`/`repair` は安全に拒否する。
- CLI は Core を直接呼び、MCP は optional で prerequisite ではない。

## 受入基準

1. `agent list`、`install`、`doctor`、`repair`、`detach` はすべて明示的 repository context を要求し尊重する。
2. A/B repository を並行操作しても identity、manifest、adapter ownership、state は完全に分離される。
3. Detection は read-only であり、`attach` と `--provider auto` は Agent host/global file を書かない。
4. 明示的 install は idempotent で無関係な bytes を保持し、strict な `.ai/adapters/<provider>.json` ownership record を書く。
5. duplicate marker、repository mismatch、symlink/reparse target、malformed section、変更済み managed content は fail closed する。
6. `agent doctor --json` は規定の state machine と標準 exit code を導出し、repository-bound probe が一致する ID を返した場合だけ `VERIFIED` にする。
7. MCP が利用できなくても CLI は完全に動作し、global MCP config を変更しない。
8. 英中日ドキュメントは discovery、install、connect、verify、compliance を区別する。
9. 既存の fmt、Clippy、package、Windows runtime、V1 Oracle gate は継続して green である。

## 必要な証拠

Protocol/manifest、provider detection/ownership、A/B isolation、managed section の
idempotency/preservation、conflict/detach fail-closed、doctor state/exit-code、MCP
なしの CLI、global write なし、三言語 parity、および Hosted quality/Windows runtime/V1 Oracle の receipt。
