# WI-39 — 显式 Agent Discovery / Adapter 层

## 意图和目标

在不引入治理决定的前提下，引入显式、可验证、可回滚的 Agent Discovery /
Adapter 层。Runtime 安装、repository attach、discovery、连接和合规仍然是
彼此独立的状态。

## 范围与非范围

范围内：provider-neutral adapter contract；canonical manifest/version 处理；
provider 检测与显式安装计划；repository-local ownership 记录；fail-closed 的
doctor/repair/detach 行为；标准状态与退出码；CLI-first 运行；以及中英日文档同步。

范围外：`attach` 自动注入 provider、全局 MCP 或 home 配置、把 Agent prompt
当作治理权威、自动生成 Work Item 决定、公开 Release/Homebrew 变更，以及
`--force` detach 快捷方式。

## 硬约束

- 每个操作都必须显式带 `--repo`，Core 不保存全局 current project。
- `attach` 仍属于 Layer 2，不修改 Agent 宿主文件。
- `.ai/agent-interface.json` 只包含 discovery facts；未知字段和不兼容版本必须 fail closed。
- `agent install` 是 Adapter 的唯一正常写入口。
- Managed 内容由 repository-local digest 记录拥有，并保留无关用户内容。
- Managed 内容被修改或存在歧义时，`detach`/`repair` 必须安全拒绝。
- CLI 直接调用 Core；MCP 是可选能力，不是前置依赖。

## 验收标准

1. `agent list`、`install`、`doctor`、`repair`、`detach` 都要求并尊重显式 repository context。
2. A/B 两个 repository 可并行操作，identity、manifest、adapter ownership 和状态完全隔离。
3. Detection 只读；`attach` 和 `--provider auto` 不写 Agent 宿主/全局文件。
4. 显式安装幂等、保留无关字节，并写入严格的 `.ai/adapters/<provider>.json` ownership record。
5. 重复 marker、repository mismatch、symlink/reparse 目标、畸形 section 和被修改的 managed 内容都必须 fail closed。
6. `agent doctor --json` 推导规定的状态机和标准退出码；只有 repository-bound probe 返回匹配 ID 才能是 `VERIFIED`。
7. MCP 不可用时 CLI 仍完整可用，且不修改全局 MCP 配置。
8. 中英日文档区分 discovery、安装、连接、验证和合规。
9. 既有 fmt、Clippy、package、Windows runtime 和 V1 Oracle gates 继续通过。

## 所需证据

Protocol/manifest 测试；provider detection 与 ownership 测试；A/B 隔离；managed section
幂等与保留测试；冲突/detach fail-closed 测试；doctor 状态/退出码测试；无 MCP 的 CLI 测试；
无全局写入测试；三语文档一致性；以及 Hosted quality、Windows runtime、V1 Oracle 回执。
