# WI-29 — Collision-Free Parallel Test Repositories

## Intent and Goal

Repair the workspace-gate race found during WI-28 verification: test binaries
must not select the same temporary repository when Rust executes tests in
parallel.

## Scope and Out of Scope

In scope: every integration-test helper that currently uses wall-clock
nanoseconds alone, plus repeated and full-workspace regression evidence.

Out of scope: production temporary-file behavior, runtime repository semantics,
WI-28 governance detection behavior, external CI execution, and release work.

## Sources and Unknowns

Source: `cargo test --workspace --quiet` failed in
`crates/cockpit-cli/tests/attach.rs` because two `git init` calls selected
`cockpit-attach-1787276227293393000`; Git reported an existing hook template and
the following attach saw an invalid repository.

Known: multiple integration-test files repeat the same PID-free, sequence-free
timestamp naming pattern. WI-26 corrected only MCP security fixtures.

Unknowns: none within this test-only corrective boundary.

## Acceptance Criteria

1. Every vulnerable helper includes process ID, nanosecond time, and a
   process-local atomic sequence.
2. No production source changes are made by WI-29.
3. Repeated attach and affected integration tests remain deterministic.
4. Two complete workspace runs and all static gates pass before WI-28 resumes.

## Required Evidence

Recorded RED failure; repeated focused tests; two workspace runs; Clippy, fmt,
diff, workflow, and multilingual checks.
