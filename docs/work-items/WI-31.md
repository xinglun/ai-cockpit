# WI-31 — Executable Runtime Identity Binding

## Intent and Goal

Bind AI Cockpit runtime identity claims and verification evidence to the exact
executing binary rather than to a version-label placeholder.

## Scope and Out of Scope

In scope: one per-invocation RuntimeContext, streaming executable SHA-256,
CLI inspect/doctor/verify propagation, explicit MCP context injection, and
consumer-visible identity tests.

Out of scope: repository attach, profile confirmation, commit/push, hosted CI,
release signing, package-archive identity, and evidence reuse (reserved for
WI-32).

## Sources and Unknowns

Sources: user-authorized WI-31 design; execution specification sections 5, 8,
13, 18, and 26; Repository Protocol v1; current CLI/MCP placeholder call sites;
and the locked V1 trust boundary as an evidence reference.

Known: the built candidate file digest does not equal the digest of the literal
`ai-cockpit-0.1.0` currently written into outputs and evidence.

Unknowns: final release artifact/signature identity remains a release concern,
not a runtime-evidence substitute. No Unknown blocks this local implementation.

## Acceptance Criteria

1. Runtime version comes from the package version and protocol version remains
   independently typed.
2. Runtime digest equals SHA-256 of the exact executing file.
3. One immutable RuntimeContext is reused across CLI and MCP per invocation.
4. Inspect, doctor, CLI verification evidence, MCP initialize, and MCP
   verification evidence expose the same supplied identity.
5. Executable discovery/read failure is fail closed.
6. No production source retains the version-string digest placeholder.
7. This Work Item creates no repository `.ai/` state.

## Required Evidence

Focused RED/GREEN and mutation tests; exact binary comparisons; two workspace
runs; Clippy, fmt, diff, workflow, multilingual, performance observation, and
locked executable V1 Oracle checks.

  test executable digest was different.
