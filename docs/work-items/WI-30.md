# WI-30 — Self-Governance Cutover Readiness

## Intent and Goal

Prepare a truthful, fail-closed transition from Markdown Bootstrap governance
to this repository being governed by its own Rust AI Cockpit runtime.

## Scope and Out of Scope

In scope: cutover preconditions, exact binary identity, explicit attach/profile
human decisions, thin `.ai/` state verification, doctor/status checks, and one
first governed lifecycle exercise.

Out of scope: V1 installation, copying runtime code or schemas into the
repository, silently attaching a dirty worktree, commit or push without human
authority, hosted CI dispatch, tag, release, and unrelated feature work.

## Sources and Unknowns

Sources: user clarification that AI Cockpit is not currently installed; product
specification sections 3–5; `docs/work-items/README.md`; repository protocol v1;
the implemented Rust `attach`, `status`, `doctor`, and lifecycle commands.

Known: `.ai/` is absent, so current Work Items are manual Bootstrap records.
The Rust attach operation is designed to write only protocol facts.

Unknown: the integrated revision to cut over from and human authority for
commit/integration, repository attach, and profile confirmation. These remain
explicit stop conditions.

## Acceptance Criteria

1. WI-25 through WI-29 are reviewed and integrated into a clean identified
   revision before attach.
2. The exact runtime binary version and SHA-256 digest are recorded.
3. Explicit human approval precedes attach and profile confirmation.
4. Attach creates only `.ai/` facts and copies no runtime implementation.
5. Status and doctor confirm protocol compatibility and no repository runtime
   code.
6. A first governed lifecycle exercise proves the central preflight and human
   close path before Bootstrap is retired.
7. Bootstrap documentation changes only after all cutover evidence is green.

## Required Evidence

Clean revision, full local gates, executable V1 Oracle, binary digest, attach
diff, status/doctor receipts, human profile decision, and first governed
lifecycle receipts.
