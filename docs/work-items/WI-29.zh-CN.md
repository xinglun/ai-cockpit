# WI-29 — 无碰撞并行测试仓库

## 意图与目标

修复 WI-28 完整门禁发现的竞态：Rust 并行执行测试时，不同测试不能选择同一个
临时 repository。

## 范围与非范围

范围内：所有只用 wall-clock nanoseconds 的 integration-test helper，以及重复和完整
workspace 回归。范围外：生产临时文件行为、Runtime repository 语义、WI-28 治理检测、
外部 CI 与发布。

## 来源与未知项

来源：`cargo test --workspace --quiet` 在 `attach.rs` 失败；两个 `git init` 选择了
同一个 `cockpit-attach-1787276227293393000`，Git 报告 hook template 已存在，随后
attach 看到无效 repository。

已知：多个测试文件重复了缺少 PID 与 sequence 的 timestamp 命名；WI-26 只修复了
MCP security fixture。该测试专用修复范围内无未知项。

## 验收标准

1. 所有易碰撞 helper 包含 PID、nanosecond 与进程内 atomic sequence。
2. WI-29 不修改生产代码。
3. 重复 attach 与相关 integration tests 保持确定性。
4. 恢复 WI-28 前，两轮完整 workspace 与全部静态门禁通过。
