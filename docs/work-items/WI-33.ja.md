# WI-33 — Cross-Process Evidence Reuse Integration

## 意図と目標

Accepted WI-32 reuse core を calibrated Project Profile、atomic content-addressed
receipt store、shared CLI/MCP verification service に接続し、安全な reuse を process
exit 後も利用可能にする。

## Scope と Out of Scope

Scope は profile-authorized reusable command、complete repository context、schema
evolution、bounded output identity、immutable receipt + atomic index、two-process
CLI/MCP parity、invalidation、cost telemetry。

Out of Scope は current repository attach、hosted provider attestation、profile redesign、
commit/push、hosted CI、signing、publication、release。

## Sources と Unknowns

Sources は accepted WI-32、execution specification section 13–16/22–24、Repository
Protocol v1、confirmed Project Profile behavior、current snapshot/repository/CLI/MCP
code、locked commit `e5acb677da6621004d96f0ef353c58fe8d3acfbf` の V1
evidence-reuse references。

Known: reusable receipt を load/write する production path はなく、全 CLI/MCP project
command は protected policy で execute する。

Unknown: hosted runner/provider attestation と long-term receipt retention は後続 WI。
Local cross-process design を block する Unknown はない。

## Acceptance Criteria

1. `calibrated` profile の exact `verified` command のみ reusable。
2. One immutable pre-run authorization read から complete profile-bound context を派生し、
   post-run snapshot と raw identity recheck は新しい内容を再 authorize しない。
3. Receipt/index store は content-addressed、strict、atomic、path-safe。
4. First successful run は evidence を persist、unchanged second process は zero spawn reuse。
5. 全 identity change と missing/untrusted store state は execute。
6. Failed command は passed receipt を作らず、output identity は bounded。
7. Protected command は毎回 execute、skipped count は zero。
8. CLI/MCP は one service を consume し equivalent node/metric evidence を公開。
9. Normal verification は historical receipt directory を scan しない。
10. この WI は development repository に `.ai/` state を作らない。
