# WI-109 — Lifecycle serial-order contract

## Goal

Make the Work Item lifecycle fail closed when governance steps are skipped or
repeated. The Runtime records the preflight decision and snapshot binding,
requires one checkpoint before verification/finish, and preserves active state
when a transition cannot proceed.

## Scope

- enforce ordered transitions in the repository lifecycle service;
- expose the same preflight receipt behavior through CLI and MCP;
- reject duplicate checkpoints and invalid finish/archive/close states;
- keep verification evidence integrity checks unconditional;
- add negative and recovery regression tests;
- document the lifecycle contract in the three reader-facing language routes.

## Boundaries

The change does not add approval rules, change Contract meaning, rewrite
historical Work Items, or edit global Agent/MCP configuration. A yellow
preflight caused only by evidence that the next lifecycle step will collect may
be checkpointed; finish still requires the post-verification decision to be
green.

## Acceptance

1. `start → verify → finish` cannot complete without recorded preflight and one
   checkpoint.
2. A red preflight cannot checkpoint; a duplicate checkpoint fails without
   changing the summary.
3. Verification refreshes the preflight binding for the resulting snapshot and
   a valid Work Item can finish, archive, and close in order.
4. Tampered verification evidence is rejected by finish/archive/close even when
   `requiredEvidenceClasses` is empty.
5. Failed transitions preserve active records for recovery.
6. CLI and MCP use the same repository-local preflight semantics.

## Verification

- `cargo test --locked -p cockpit-repository --all-targets --all-features -- --test-threads=1`
- `cargo test --locked -p cockpit-cli --all-targets --all-features -- --test-threads=1`
- workspace formatting, clippy, and full test gates before merge.
