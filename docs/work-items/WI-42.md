# WI-42 — Documentation governance and Agent route

## Intent and goal

Make the current documentation truthful after self-governance and public
`v0.1.1` release. The reader route must explain what an installed shared Runtime
does, how a repository is attached, and how an Agent is explicitly connected;
internal implementation history must not be presented as current product status.

## Scope

- remove stale progress, pre-self-governance, and WI-35-pending claims from the
  public documentation home and release architecture;
- keep English, Chinese, and Japanese README and Work Item routes aligned;
- add repository-local `.ai/README.md` and `.ai/glossary.md` as the Agent-facing
  usage and vocabulary entry;
- add concise usage guidance to the repository-owned `AGENTS.md` section without
  changing any global Agent or MCP configuration;
- retain historical Work Items in Git as audit records, not as adopter guidance.

## Acceptance

1. No public documentation home claims that this repository is unattached, that
   the Runtime cannot govern itself, or that the `v0.1.1` public Release is still
   pending.
2. Root and documentation README language links are reciprocal and the route is
   organized by reader goal rather than implementation chronology.
3. `.ai/README.md` gives an Agent explicit `--repo` commands, lifecycle order,
   adapter boundary, and evidence discipline; it never invents a governance
   result.
4. `.ai/glossary.md` distinguishes shared Runtime, Repository Context, Adapter,
   Work Item, evidence, and migration terms.
5. `AGENTS.md` points to the repository-local route and does not alter the
   managed adapter section or global configuration.
6. All three `docs/work-items/README*` files describe installed-runtime
   self-governance and no V1 `make ai-*` workflow.

## Evidence

Verification covers documentation scans, Agent doctor ownership, link checks,
and the installed Runtime verification receipt for this Work Item.

## Outcome

The public docs and Agent route are current. Runtime migration behavior is a
separate WI-43 concern and is not inferred from documentation alone.
