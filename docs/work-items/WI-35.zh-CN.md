# WI-35 — 首次公开发布与 Homebrew Tap 初始化

## 意图与目标

从本地已达到 configuration-complete 的 WI-34 candidate 执行首次外部 hosted release。发布准确的
不可变 GitHub Release，通过 identity-bound pull request 初始化受保护的 Homebrew tap，并记录真实
安装回执；不改变 runtime 语义，也不在本仓库安装 V1。

## 范围与明确不属于范围

范围内：显式 hosted workflow dispatch 或 tag 执行；在批准的 source commit 上保留不可变的
`v0.1.0` tag；hosted source、target build、manifest、archive、SBOM、smoke 和 provenance 回执；
GitHub Release 发布；创建并保护 `xinglun/homebrew-tap`；验证准确的 `homebrew-handoff.json`；
identity-bound Formula pull request；Homebrew install、test、uninstall 与公开 archive 安装回执；
以及最终 release 状态报告。

范围外：修改 Rust governance 语义；将 `cockpit.toml` 改为 JSON；安装 V1；直接写 tap 的 default branch；
`curl | sh`；Linuxbrew；crates.io 发布；宽泛 ABI 声明；在本 development checkout 中 attach repository；
以及没有明确 external-write 授权的任何 release action。

## 来源与未知项

来源：已接受的 WI-34 及其三语 design/plan；准确的 release workflow 与 `cockpit-release` validator；
GitHub hosted-runner 与 artifact-attestation 文档；Homebrew tap/Formula 指南；受保护 tap repository policy；
以及 WI-34 的 post-publication handoff contract。

已知：WI-34 已证明本地 candidate、workflow policy、严格 manifest/Formula/handoff 类型、Cargo Git fixture、
V1 Oracle 和本地质量 gate。当前 remote 没有公开 `v0.1.0` tag、provider Release 或 `xinglun/homebrew-tap`。

阻塞执行的未知项：tap 所有权与 branch protection、GitHub App 或最小权限 credential、hosted runner 结果、
provider Release identity、attestation ID，以及真实 adopter 安装结果。

## 验收标准

1. 人类授权的 hosted run 绑定到准确归档的 WI-34 commit；tag event 必须是新的不可变 `v0.1.0` reservation，
   移动或复用 tag 必须 fail closed。
2. Source-quality、release-policy、五个 target build、archive/member 检查、manifest/checksum、
   Homebrew/Linux/Windows smoke 以及最终 candidate attestation 在同一次 run 中全部通过。
3. Provider Release 只包含明确 allowlist 中的 manifest、checksum、Formula、五个 archive 与五个 SBOM；
   每个制品都必须与 canonical manifest 和 attestation subject 一致。
4. Provider Release identity、tag target、workflow commit、lockfile digest、binary version 和 provider
   Release ID 必须被记录并独立校验。
5. `xinglun/homebrew-tap` 已创建或确认，`main` 受到保护，准确的 Formula handoff 打开可审查 PR；不得直接写
   default branch。
6. 从指定 source run 取得 handoff，校验其 attestation 与 expiry，并确认 destination、commit、manifest digest、
   Formula digest、provider Release ID 和 action 都与 PR 一致。
7. 在支持的 macOS ARM64/Intel host 上记录 Homebrew install、`brew test`、`ai-cockpit --version`、uninstall
   和 link removal；在声明的 Linux/Windows runner 上记录 archive checksum、解压、`--version`、`--help` 回执。
8. 第二个公开版本存在后，rollback 回执必须命名不可变的 prior Release；在此之前只记录首次 release 的 rollback
   过程，不伪造 upgrade 结果。
9. development repository 继续没有 `.ai/`，不安装 V1；发布过程不改变 runtime code 或配置格式。

## 所需证据

Hosted run ID 与 commit binding；tag/ref event payload；source-quality 与 smoke job 结论；release manifest、
`SHA256SUMS`、SBOM、archive digest 与 attestation ID；provider Release URL/ID 与 asset inventory；受保护 tap 设置；
已签名/attested 的 `homebrew-handoff.json`；Formula PR URL、diff 与 merge commit；macOS Homebrew install/test/uninstall
回执；Linux/Windows archive 回执；第二个版本存在时的 rollback/upgrade 回执；两位独立 reviewer；以及所有跳过或失败
的 external step 的明确记录。引用 WI-34 本地证据，不将其改写为 hosted 证据。
