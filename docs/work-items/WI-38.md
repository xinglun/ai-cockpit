# WI-38 — Governance Scaffolding Without Governance Decisions

## Intent and Goal

Introduce governance scaffolding without introducing governance decisions.
The shared Rust Core stays external and stateless; each explicitly bound
repository receives only a deterministic, validator-readable skeleton.

## Scope and Out of Scope

In scope: minimum `attach` scaffold, repository-local discovery manifest,
`work-item new`, the shared scaffold API used by transitional `start`,
read-only `profile propose`, isolation tests, and synchronized user
documentation. Out of scope: Agent provider injection, global MCP changes,
automatic authority/intent/acceptance, profile baseline application, or
business-project templates.

## Hard Constraints

- `attach` creates protocol state and repository identity only; it does not
  mutate `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, `.cursor/**`, or user-global
  MCP configuration.
- `work-item new` fills only snapshot-derived facts. Intent, scope, acceptance
  criteria, and authority remain empty or `unknown`.
- A skeleton is `not_ready`/`unknown` and never claims `passed`, `approved`,
  `verified`, or `completed`.
- `profile propose` is candidate/proposed and cannot modify formal baseline
  bytes or digest without a separate explicit apply flow.
- Every CLI command requires explicit `--repo`; no process-level current
  project state is introduced.

## Acceptance Criteria

1. Repeated attach is byte-stable and creates no meaningless diff.
2. Parallel A/B attach and Work Item scaffolding isolate IDs, snapshots,
   profiles, Contracts, and evidence.
3. `work-item new` fills `repositoryId`, `baseRevision`,
   `projectProfileDigest`, and `repositorySnapshotDigest`.
4. Human-owned fields are not inferred and the validator remains not-ready.
5. Profile proposal leaves the formal profile unchanged and is explicitly
   marked candidate/proposed.
6. No provider or global-agent files are written.
7. English, Chinese, and Japanese docs explain the boundary and list the
   missing human inputs in the command output.

## Required Evidence

Focused repository/protocol/CLI tests, parallel repository isolation test,
profile baseline byte comparison, format, Clippy, diff, full package tests,
and documentation parity/readability review.
