# WI-37 — 共享 Runtime 与 Repository Context 隔离

## Intent 与 Goal

将 Rust Core 定义为机器级共享、工程外部安装的 Runtime。只有显式请求 context 才能绑定
repository；Contract、evidence、knowledge 和 profile 始终由各 repository 独立持有。

## Scope 与 Out of Scope

范围：attach 稳定的 `repositoryId`、显式 `--repo` 文档与请求绑定架构图、移动目录回归测试、
Hosted CI 中的 package test 隔离。不在范围：把 `cockpit.toml` 改为 JSON、把 Runtime code
复制到 repository、全局 active repository 状态、Agent provider adapter 或公开发布。

## Sources 与 Unknowns

来源：已批准的 shared-Runtime/three-layer design、Repository Protocol v1、当前 Rust CLI、
repository service 和 Runtime topology 文档。

已知：CLI/MCP 已按请求接收 repository path；attach 以前根据绝对路径生成 identity。
下一 Agent Discovery Work Item 负责 provider manifest、managed adapter ownership 和 MCP
client discovery。

## Acceptance Criteria

1. `attach` 一次生成有效 digest identity；repository 目录移动后再次 attach 仍读取同一 identity。
2. Core API 不引入全局 current repository、Work Item 或 profile；repository-bound CLI/MCP
   operation 继续要求显式 context。
3. 英文、中文、日文的 architecture、Runtime topology、configuration 和 entry 文档都展示一份
   共享 Runtime 与隔离的 Repository Context。
4. Hosted quality 不并发运行会启动进程的 package binary；V1 Oracle 和 Windows runtime check 仍是必需项。

## Required Evidence

attach/move、repository receipt、verification-service、CLI、Clippy、format、diff、Hosted quality、
Windows runtime 和 V1 Oracle 结果。
