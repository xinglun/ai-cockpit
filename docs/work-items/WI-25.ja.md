# WI-25 — Governance Trust Chain の閉鎖

## 意図と目標

受入れ監査で見つかった lifecycle の trust-chain 欠陥を修正する。現在の
governance decision が red の場合、passed command だけで Work Item を完了できない
こと、scope 内の通常の実装変更で Contract が stale にならないこと、verification
evidence が検証コマンド後の repository snapshot に束縛されることを保証する。

## 範囲と非範囲

範囲：Contract freshness semantics、repository lifecycle finish gate、CLI/MCP の
verification snapshot binding、scope 内外の変更に対する regression test。

非範囲：V1 installer/template parity、新しい evidence class、self-governance
cutover、release publication、無関係な capability 追加。

## Sources と Unknowns

Sources は `docs/work-items/README.md`、`docs/architecture.md`、
`tests/conformance/manifest.json`、および reference commit
`e5acb677da6621004d96f0ef353c58fe8d3acfbf` に対する受入れ監査である。

既知：現在の実装は red preflight 後の finish を許し、CLI/MCP verification を
コマンド実行前の snapshot に束縛している。

未知：将来 commit 済み Work Item 変更に別の base-diff provider が必要かどうか。
本 WI では既存の working-tree protocol を維持し、その provider は導入しない。

## 受入れ基準

1. scope または freshness が red の場合、finish、archive、close は拒否される。
2. `start` 後の scope 内 working-tree 変更は、現在 snapshot が異なるだけで stale
   Contract にならない。
3. verification command 完了後の repository snapshot が evidence に記録される。
4. CLI と MCP が同じ修正済み evidence/lifecycle semantics を使用する。
5. 既存の conformance、lifecycle、security、performance test が通過する。

## 必須 Evidence

- failing から passing になる lifecycle regression test。
- verification snapshot binding regression test。
- `cargo test --workspace`、clippy、fmt、diff check。

## 検証

- RED を実装前に確認した。scope 内変更が `stale_contract` になり、scope 外の
  finish が通ること、`cargo check` の副作用で receipt が stale になることを再現した。
- GREEN：`cargo test --workspace`、clippy、fmt、diff check。
- CLI/MCP の lifecycle/verification focused test も GREEN。
- archive と close が lifecycle transition 後に governance を再確認する test も GREEN。

承認していない。

## Outcome

Status: **Implemented**。Finish は現在の governance decision を再評価し、Contract
freshness は baseline-oriented、CLI/MCP verification evidence は command 後の snapshot
を使用する。GA は別の監査 findings に依存し、本 WI は self-governance や release closure
を主張しない。
