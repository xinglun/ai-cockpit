# WI-38 — ガバナンス判断を作らないガバナンス・スキャフォールド

## Intent と Goal

ガバナンス判断を導入せずに、ガバナンス用の最小スキャフォールドを提供します。Rust Core は外部に
1 つだけ置くステートレスな共有 Runtime のまま、明示的に bind された各 repository には決定的に導ける
検証可能な骨格だけを作成します。

## Scope と Out of Scope

対象：最小 `attach` スキャフォールド、repository ローカルの discovery manifest、`work-item new`、
移行期の `start` と共有する contract scaffold API、デフォルト read-only の `profile propose`、分離テスト、
三言語の利用者向け文書。対象外：Agent provider の注入、global MCP の変更、authority/intent/acceptance の自動生成、
正式 profile baseline の適用、業務プロジェクト用テンプレート。

## Hard Constraints

- `attach` は protocol state と repository identity だけを作成し、`AGENTS.md`、`CLAUDE.md`、`GEMINI.md`、
  `.cursor/**`、ユーザー全体の MCP 設定を変更しません。
- `work-item new` が埋められるのは現在の snapshot から決定的に導ける事実だけです。intent、scope、acceptance criteria、
  authority は空または `unknown` のままにします。
- 骨格の状態は `not_ready`/`unknown` とし、`passed`、`approved`、`verified`、`completed` を生成しません。
- `profile propose` は candidate/proposed と明示し、独立した明示的 apply 手続きなしには正式 baseline の bytes/digest を変更しません。
- すべての CLI コマンドは明示的な `--repo` を要求し、process-level の current project state を導入しません。

## Acceptance Criteria

1. attach を繰り返しても byte-stable で、意味のない差分を作りません。
2. A/B の repository を並行 attach・Work Item 作成しても ID、snapshot、profile、Contract、evidence は分離されます。
3. `work-item new` は `repositoryId`、`baseRevision`、`projectProfileDigest`、`repositorySnapshotDigest` を埋めます。
4. 人間所有のフィールドを推測せず、既存 validator は not-ready を返します。
5. profile proposal は正式 profile を変更せず、candidate/proposed と明示します。
6. provider ファイルや global Agent 設定を書き込みません。
7. 英語・中国語・日本語の文書が同じ境界と不足している人間入力を説明します。

## Required Evidence

repository/protocol/CLI focused test、並行 isolation test、profile baseline の byte 比較、format、Clippy、diff、全 package test、
文書 parity/readability review。

## Human Decisions

この Work Item は実装と文書だけを許可します。public Release、Homebrew tap、provider 注入、global MCP 設定変更は許可しません。
