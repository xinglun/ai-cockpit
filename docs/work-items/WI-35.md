# WI-35 — First Public Release and Homebrew Tap Bootstrap

## Intent and Goal

Execute the first externally hosted release from the locally configuration-complete
WI-34 candidate. Publish the exact immutable GitHub Release, bootstrap the protected
Homebrew tap through an identity-bound pull request, and record real installation
receipts without changing runtime semantics or installing V1 into this repository.

## Scope and Out of Scope

In scope: explicit hosted workflow dispatch or tag execution; immutable `v0.1.0`
tag reservation on the approved source commit; hosted source, target-build,
manifest, archive, SBOM, smoke, and provenance receipts; GitHub Release publication;
creation and protection of `xinglun/homebrew-tap`; verification of the exact
`homebrew-handoff.json`; an identity-bound Formula pull request; Homebrew install,
test, uninstall, and public archive installation receipts; and the final release
state report.

Out of scope: changing Rust governance semantics; changing `cockpit.toml` to JSON;
V1 installation; direct default-branch writes to the tap; `curl | sh`; Linuxbrew;
crates.io publication; broad ABI claims; repository attach in this development
checkout; and any release action without explicit external-write authorization.

## Sources and Unknowns

Sources: locally accepted WI-34 and its three-language design/plan; the exact
release workflow and `cockpit-release` validators; the GitHub hosted-runner and
artifact-attestation documentation; Homebrew tap/Formula guidance; the protected
tap repository policy; and the WI-34 post-publication handoff contract.

Known: WI-34 proves the local candidate, workflow policy, strict manifest/Formula/
handoff types, Cargo Git fixture, V1 Oracle, and local quality gates. The current
remote has no reserved public `v0.1.0` tag, provider Release, or `xinglun/homebrew-tap`.

Unknowns that block execution until external state changes: tap ownership and
branch protection, GitHub App or narrowly scoped credential, hosted runner results,
provider Release identity, attestation IDs, and real adopter installation results.

## Acceptance Criteria

1. A human-authorized hosted run is bound to the exact archived WI-34 commit and
   the tag event is a new immutable `v0.1.0` reservation; a moved or reused tag
   fails closed.
2. Source-quality, release-policy, all five target builds, archive/member checks,
   manifest/checksum validation, Homebrew/Linux/Windows smoke jobs, and final
   candidate attestation all pass in the same run.
3. The provider Release contains only the explicitly allowlisted manifest,
   checksum, Formula, five archives, and five SBOMs; every asset agrees with the
   canonical manifest and attestation subjects.
4. The public Release identity, tag target, workflow commit, lockfile digest,
   binary version, and provider Release ID are recorded and independently checked.
5. `xinglun/homebrew-tap` is created or confirmed with protected `main`, and the
   exact Formula handoff opens a reviewable PR. No default-branch direct push occurs.
6. The handoff is retrieved from the named source run, its attestation and expiry
   are verified, and its destination, commit, manifest digest, Formula digest,
   provider Release ID, and action all match the PR.
7. On supported macOS ARM64 and Intel hosts, Homebrew install, `brew test`,
   `ai-cockpit --version`, uninstall, and link removal are recorded. Linux and
   Windows archive checksum, extraction, `--version`, and `--help` receipts are
   recorded on their declared runners.
8. A rollback receipt names an immutable prior Release when a second public
   version exists; until then, the first-release rollback procedure is documented
   but not represented as a fabricated upgrade result.
9. The development repository remains without `.ai/`, no V1 files are installed,
   and no runtime code or configuration format is changed as part of publication.

job conclusions; release manifest, `SHA256SUMS`, SBOMs, archive digests and
attestation IDs; provider Release URL/ID and asset inventory; protected tap

commit; macOS Homebrew install/test/uninstall receipts; Linux and Windows archive
receipts; optional rollback/upgrade receipt when a second version exists; two
independent reviewers; and an explicit record of every skipped or failed external
step. Local WI-34 evidence is referenced, not rewritten as hosted evidence.
