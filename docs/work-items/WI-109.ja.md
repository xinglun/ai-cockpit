# WI-109 — Lifecycle の serial-order contract

## 目的

Governance step が省略または重複されたときに Work Item lifecycle を fail closed
にします。Runtime は preflight decision と snapshot binding を記録し、
verification/finish の前に 1 回の checkpoint を要求します。transition が進めない
場合は active state を保持します。

## Scope

- repository lifecycle service で順序付き transition を強制する;
- CLI と MCP で同じ repository-local preflight receipt を使う;
- duplicate checkpoint と順序外の finish/archive/close を拒否する;
- verification evidence の integrity check を常に適用する;
- negative と recovery の regression test を追加する;
- 3 言語の reader-facing documentation に lifecycle contract を記載する。

## 境界

approval rule の追加、Contract の意味の変更、historical Work Item の書き換え、
global Agent/MCP configuration の編集は行いません。次の lifecycle step で収集する
evidence がまだないことだけが理由の yellow は checkpoint へ進めますが、finish には
verification 後の green decision が必要です。

## 受入れ条件

1. 記録済み preflight と 1 回の checkpoint がなければ `start → verify → finish` は
   完了できない。
2. red preflight は checkpoint を拒否し、duplicate checkpoint は summary を変更せず
   fail closed する。
3. verification は最終 snapshot に対する preflight binding を refresh し、valid な
   Work Item は finish、archive、close を順序どおり完了できる。
4. `requiredEvidenceClasses` が空でも、tampered verification evidence を
   finish/archive/close は拒否する。
5. 失敗した transition は active record を保持し、復旧できる。
6. CLI と MCP は同じ repository-local preflight semantics を利用する。

## 検証

- `cargo test --locked -p cockpit-repository --all-targets --all-features -- --test-threads=1`
- `cargo test --locked -p cockpit-cli --all-targets --all-features -- --test-threads=1`
- merge 前に workspace fmt、clippy、full test gate を実行する。
