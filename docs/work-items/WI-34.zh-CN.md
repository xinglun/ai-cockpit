## 意图与目标

Cargo Git fallback 所共用的确定、可测试安装契约，同时不声称已经公开发布。

## 范围与非范围

范围内：严格的 release manifest 与版本绑定；稳定 archive 布局；确定性的 macOS
ARM64/Intel Formula 生成；source、archive、checksum、SBOM 与 provenance 一致性；
staged install/uninstall/upgrade 测试；跨仓库 handoff；最小权限 release workflow
设计；以及中英日三语安装文档。

范围外：把 `cockpit.toml` 改成 JSON；安装 V1；Linuxbrew Formula；crates.io 发布；
创建 `xinglun/homebrew-tap`；commit/push；托管 workflow dispatch；创建 tag 或
GitHub Release；创建/合并 tap PR；repository attach；以及声称安装已公开可用。

## 验收标准

1. 校验 tag、workspace、package、binary、commit、lockfile、archive 与 manifest
   identity，任何不一致均 fail closed。
2. 五个 target archive 使用统一稳定布局、一个 canonical manifest 与 checksum 集。
3. macOS ARM64/Intel Formula 生成严格、确定且完整，使用精确 HTTPS URL 与 SHA-256。
4. 手动 dispatch 不能发布；tag 发布必须通过 source、artifact、manifest、smoke、
   SBOM、provenance 与 release 全部门禁。
5. 跨仓库 Formula 交付采用 identity-bound PR handoff，不使用默认 token 直接写入默认分支。
6. 完整定义 Hosted fixture job，使其能在当前 ARM64/Intel runner 上执行 Homebrew
   install/test/uninstall 且无需公开 Release；实际运行与 hosted 回执归 WI-35。
7. 本地 archive/Cargo Git fixture 与 workflow policy 测试证明 fallback 达到配置完成；
   hosted Linux/Windows 回执归 WI-35。
8. 三语文档覆盖安装、验证、升级、卸载、回滚、手动 archive、Cargo Git、MCP 及
   install 与 attach 的区别。
9. 不引入 `curl | sh` 主安装器、Linuxbrew 声明、crates.io 声明、mutable tag 复用或
   未验证的公开安装声明。
10. 本开发仓库继续不存在 `.ai/`。
