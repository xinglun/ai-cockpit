# WI-25 — 闭合治理信任链

## 意图与目标

修复验收发现的生命周期信任链缺陷：当前治理决策为 red 时不能仅凭通过的
命令完成 Work Item；scope 内的正常实现变化不能使自身 Contract 失效；验证证据
必须绑定验证命令完成后的仓库快照。

## 范围与非范围

范围：Contract 新鲜度语义、Repository lifecycle finish 门禁、CLI/MCP 验证快照
绑定，以及 scope 内/越界变化的回归测试。

非范围：V1 installer/template parity、全新证据类型、自治理切换、正式发布和无关
能力扩展。

## 来源与未知项

来源：`docs/work-items/README.md`、`docs/architecture.md`、
`tests/conformance/manifest.json`，以及针对参考提交
`e5acb677da6621004d96f0ef353c58fe8d3acfbf` 的验收审计。

已知：当前实现允许 red preflight 后执行 finish，并将 CLI/MCP 验证绑定到命令执行
前的快照。

未知：未来已提交的 Work Item 变化是否需要独立 base-diff provider；本 WI 保留
现有 working-tree 协议，不引入该 provider。

## 验收标准

1. scope 或 freshness 为 red 时不能 finish、archive 或 close。
2. `start` 后 scope 授权的 working-tree 变化不能仅因当前快照不同而被判定为 stale Contract。
3. 验证命令完成后生成的仓库快照必须写入 verification evidence。
4. CLI 和 MCP 使用相同的修正后证据与生命周期语义。
5. 现有 conformance、lifecycle、security、performance 测试继续通过。

## 必需证据

- 先失败后通过的生命周期回归测试。
- 验证快照绑定回归测试。
- `cargo test --workspace`。
- `cargo clippy --workspace --all-targets --all-features -- -D warnings`。
- `cargo fmt --all --check`。
- `git diff --check`。
