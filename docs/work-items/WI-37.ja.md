# WI-37 — Shared Runtime と Repository Context の分離

## Intent と Goal

Rust Core を machine に 1 つだけ install する外部 Runtime とします。repository は明示的な
request context だけで bind し、Contract、evidence、knowledge、profile は repository ごとに分離します。

## Scope と Out of Scope

対象：attach 時に安定した `repositoryId` を生成すること、明示的な `--repo` の説明と request-bound
architecture diagram、移動回帰テスト、Hosted CI の package-test 分離。対象外：`cockpit.toml` の JSON 化、
Runtime code の repository へのコピー、global active repository state、Agent provider adapter、public release。

## Sources と Unknowns

Sources は approved shared-Runtime/three-layer design、Repository Protocol v1、現在の Rust CLI、repository
service、Runtime topology document です。CLI/MCP は request ごとに repository path を受け取りますが、以前の
attach は absolute path から identity を生成していました。provider manifest、managed adapter ownership、
MCP client discovery は次の Agent Discovery Work Item の範囲です。

## Acceptance Criteria

1. `attach` は有効な digest identity を一度生成し、repository directory を移動して再 attach しても同じ identity を読み取る。
2. Core API は global な current repository、Work Item、profile を導入せず、repository-bound CLI/MCP operation は明示的な context を要求する。
3. English、Chinese、Japanese の architecture、Runtime topology、configuration、entry document が共有 Runtime と分離された Repository Context を説明する。
4. Hosted quality は process-spawning package binary を並行実行せず、V1 Oracle と Windows runtime check を必須として維持する。

## Required Evidence

attach/move、repository receipt、verification-service、CLI、Clippy、format、diff、Hosted quality、Windows runtime、V1 Oracle の結果。
