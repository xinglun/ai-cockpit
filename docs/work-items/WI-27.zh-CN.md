# WI-27 — 可执行 V1 行为 Oracle

## 意图与目标

用外部 V1 参考 Runtime 的可执行、提交锁定行为证据，取代离线 corpus
对 V1 parity 的自声明。

## 范围与非范围

范围内：测试专用 V1 adapter、Rust 信任边界集成测试、全部十四个 canonical
case、诚实的 conformance 元数据与文档，以及独立 CI Oracle job。

范围外：把 V1 复制进 Rust Runtime 或 adopter 仓库、兼容 V1 API、给产品
Runtime 增加 Python/网络依赖、自治理切换、发布以及无关治理能力。

## 来源与未知项

来源：用户执行指示第 22、24、25 节与 Gate B；V1 参考提交
`e5acb677da6621004d96f0ef353c58fe8d3acfbf`；现有 conformance manifest
与十四个 fixture；WI-27 设计文档。

已知：现有测试把 Rust 输出与本仓库人工编写的 expected JSON 比较，并明确
不执行 V1。

未知：V1 实际语义是否会与当前 V2 预期冲突。冲突必须保持 RED，直到依据
捕获的 V1 输出完成协调。

## 验收标准

1. 十四个 case 全部在精确锁定的 V1 提交上执行。
2. 每个 case 比较七个 canonical 语义字段。
3. Adapter 不能读取 V2 expected JSON。
4. 错误参考身份、依赖不可用、输出畸形或语义漂移全部失败关闭。
5. CI 执行外部 Oracle；普通产品/adopter 使用不依赖 V1、Python 或网络。
6. 英中日文档准确描述边界。

## 所需证据

聚焦 RED/GREEN Oracle 测试、错误 reference 与语义变异负向检查、两轮完整
workspace 测试、Clippy、fmt、diff、workflow 与多语言检查。
