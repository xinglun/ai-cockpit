# WI-28 — Snapshot-Derived Governance Signals

## Intent and Goal

Remove the three hard-coded safe governance inputs and derive repository input
trust, test weakening, and coverage weakening from one immutable snapshot.

## Scope and Out of Scope

In scope: process-local bounded change facts, deterministic signal analysis,
central decision wiring, CLI/MCP/lifecycle regressions, and disclosure tests.

Out of scope: V1 source copying, a second Git scan, generalized semantic code
analysis, external provider evidence, evidence-class expansion, self-governance
installation, release, and unrelated observer capabilities.

## Sources and Unknowns

Sources: user execution specification sections 10, 13, 15, 24, and 25; WI-27
executable Oracle results; the current `RepositorySnapshot` and central
`governance_decision_for_contract` implementation.

Known: the decision adapter currently supplies three literal `false` values and
the snapshot has no reusable change-line facts.

Unknown: language-specific weakening beyond the bounded cross-language signals
declared in the design. Unsupported inspection must remain explicit Unknown.

## Acceptance Criteria

1. The three production governance inputs are snapshot-derived.
2. Git observation remains four calls and happens once per decision.
3. Test deletion is Red; coverage lowering and prompt injection are Yellow.
4. Relevant uninspectable changes become Unknown/Yellow.
5. Raw source/diff text is not serialized by CLI or MCP.
6. CLI, MCP, finish, archive, and close share the central result.
