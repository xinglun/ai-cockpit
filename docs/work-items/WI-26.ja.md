# WI-26 — Deterministic MCP Security Test Fixtures

## 意図と目標

WI-25 の再受入れで検出した temporary directory race を除去し、Rust の parallel
test execution でも workspace quality gate を deterministic にする。

## 範囲と非範囲

範囲：MCP security test の repository path generator と verification evidence。

非範囲：production MCP behavior、Repository Protocol behavior、V1 Oracle integration、
self-governance、release publication、無関係な test helper。

## Sources と Unknowns

Source は最初の再受入れ `cargo test --workspace` で
`crates/cockpit-mcp/tests/security.rs:16` に発生した `AlreadyExists` と、その後の
isolated rerun pass である。

既知：同じ process 内の二つの test が同じ PID と nanosecond timestamp を取得し、
`create_dir` が失敗し得る。

この bounded correction に Unknown はない。

## 受入れ基準

1. parallel MCP security test は同じ temporary repository path を選択しない。
2. production crate behavior を変更しない。
3. MCP security test の反復実行と二回の workspace test が通過する。
4. Clippy、format、diff check が通過する。

## 必須 Evidence

- RED：最初の full reacceptance run の `AlreadyExists` failure。
- MCP security test の反復実行。
- 二回の `cargo test --workspace`。
- Clippy、fmt、diff check。
