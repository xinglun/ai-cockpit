# WI-40 — Post-release Adopter Acceptance Baseline

## 意図と目標

immutable な public Release artifact だけで再現可能な post-release adopter acceptance baseline を確立します。
実際の GitHub Release binary が、新しい adopter repository をゼロから governance できることを、失敗時も監査可能な receipt と共に証明します。

## Scope と Out of Scope

Scope は `tests/release/adopter_acceptance.sh`、public Release download/digest、isolated HOME/XDG/TMP/Cargo/adopter、
attach/profile/Agent/doctor/verify evidence、`first-adopter-smoke` の not-ready assertion、Work Item lifecycle、evidence reuse、
`acceptance.json`、directory `SHA256SUMS`、post-release `adopter_acceptance` CI、三言語 documentation です。

Out of Scope は Runtime `acceptance` command、source/Protocol change、global Agent/MCP config、pre-release gate、既存 Release truth の変更、
second technology-stack adopter です。

## Hard Constraints

- harness は Runtime を取得するために `cargo build`、`cargo run`、workspace binary、local `target` binary を使わない。
- Runtime call はすべて download binary の absolute path を使い、`runtime.json` の digest と一致させる。
- `runtime.json` は tag、version、archive digest、binary digest、platform、archive、download source、public Release state を bind する。
- post-release acceptance が失敗しても `acceptance.json` の `releasePublished: true` は維持し、後続 version に失敗 receipt を再利用しない。
- `SHA256SUMS` は自身以外の全 evidence file を覆う。
- Run ごとに独立した HOME、XDG_CONFIG_HOME、TMPDIR、CARGO_HOME、adopter repository を使う。
- `first-adopter-smoke` は `not_ready` のままにし、人間所有の field を捏造しない。

## Acceptance Criteria

1. 指定した public Release の archive、manifest、checksum だけを download し、tag/version/digest mismatch と source fallback を拒否する。
2. Runtime version/binary digest は `runtime.json`、inspect、Work Item
   verification と一致し、`doctor` は同じ repository identity を `VERIFIED` と確認する。
3. 新しい adopter が独立した repositoryId を持ち、attach、profile confirm、Agent adapter install、`VERIFIED` doctor を通過する。
4. `first-adopter-smoke` contract は `not_ready` で、人間所有 field は空または `unknown` のままである。
5. 独立 Work Item が start、checkpoint、preflight、verify、finish、archive、close、outcome、verification evidence を生成する。
6. 同じ sanitized environment の verify 二回で、最初は execute、二回目は receipt reuse と zero spawn になる。
7. source checkout に元からある `.ai` state と Git status が変わらず、adopter repository が分離され、
   HOME/XDG の前後 manifest が同じである。未 attach の checkout と自己 governance 済みの AI Cockpit source repository の両方で成立する。
8. `acceptance.json` が全 step を要約し、`SHA256SUMS` が evidence directory 全体を bind する。
9. release workflow は `publish` と `publish_handoff` 後だけ harness を実行し、成功/失敗の両方で evidence を upload し、Release truth を書き換えない。
10. English、Chinese、Japanese docs が同じ post-release boundary を説明する。

## Required Evidence

release/runtime/repository、`release-manifest.json`、attach、inspect、profile、Agent、verify、isolation JSON、not-ready contract、
全 lifecycle receipt、`acceptance.json`、`SHA256SUMS` を含む acceptance artifact が必要です。
