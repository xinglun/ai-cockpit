# WI-31 — 可执行 Runtime 身份绑定

## 意图与目标

把 AI Cockpit runtime 身份声明和 verification evidence 绑定到精确执行的 binary，
而不是版本标签占位值。

## 范围与非范围

范围内：每次调用一个 RuntimeContext、流式 executable SHA-256、CLI
inspect/doctor/verify 传播、显式 MCP context 注入及消费者可见身份测试。

范围外：repository attach、profile 确认、commit/push、托管 CI、release 签名、
package archive 身份及 evidence reuse（保留给 WI-32）。

## 来源与未知项

来源：用户批准的 WI-31 设计；执行指示第 5、8、13、18、26 节；Repository Protocol
v1；当前 CLI/MCP 占位调用点；锁定 V1 的 evidence trust boundary。

已知：候选 binary 文件 digest 与当前输出/evidence 使用的字面量
`ai-cockpit-0.1.0` digest 不一致。

未知：最终 release artifact/signature 身份仍属于 release 边界，不能替代 runtime
evidence。本地实现范围内无阻断 Unknown。

## 验收标准

1. Runtime version 来自 package version，protocol version 保持独立类型。
2. Runtime digest 等于精确执行文件的 SHA-256。
3. 每次调用的 CLI 与 MCP 复用同一个不可变 RuntimeContext。
4. Inspect、doctor、CLI verification evidence、MCP initialize 和 MCP verification
   evidence 暴露相同的传入身份。
5. Executable discovery/read 失败时 fail closed。
6. 生产源码不再保留版本字符串 digest 占位值。
7. 本 WI 不为当前仓库创建 `.ai/`。

## 所需证据

聚焦 RED/GREEN 与 mutation 测试、精确 binary 比较、两轮 workspace、Clippy、fmt、
diff、workflow、多语言、性能观察及锁定的可执行 V1 Oracle。

## 验证

- RED：inspect 返回版本标签 digest `ced29f7d...`，与精确测试 executable digest
  不同。
- RED：不存在 executable 路径测试最初因无 fail-closed loader 而编译失败。
- RED：doctor 无 runtime digest；MCP 无注入 context API；CLI evidence 保留占位
  digest；MCP evidence 保留 `0.1.0` 而不是注入的 `9.8.7-test`。
- GREEN：executable identity 流式读取一次形成单个 RuntimeContext，受影响的 CLI/MCP
  聚焦套件通过。
- Mutation 证据：恢复版本标签 digest 后精确 inspect 测试失败；恢复 executable hashing
  后重新变绿。
- 精确 optimized binary 检查：inspect 返回
  `sha256:388ed6f2aba81eaaa9c583aa3f1f9c922d706e97c70f7048605a655139ee8cad`，
  与独立 `shasum -a 256` 一致。
- 性能：12 次 release status 中位数 9.52 ms、最大 25.39 ms；debug test binary
  中位数另行记录为 306 ms。
- GREEN：两次独立 `cargo test --workspace --quiet`。
- GREEN：Clippy（拒绝 warning）、rustfmt、`git diff --check`、workflow YAML、Python
  编译、三语对应与锁定 V1 Oracle。

执行 binary。本仓库未创建 `.ai/`。集成、托管 CI、commit、attach 与 release 仍待
