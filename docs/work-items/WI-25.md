# WI-25 — Close the Governance Trust Chain

## Intent and Goal

Repair the lifecycle trust-chain defects found during acceptance: a Work Item
must not finish from a passed command while its current governance decision is
red, an in-scope implementation change must not invalidate its own Contract,
and verification evidence must bind to the repository snapshot after the
verification command has run.

## Scope and Out of Scope

In scope: Contract freshness semantics, repository lifecycle finish gating,
CLI/MCP verification snapshot binding, and regression tests for in-scope and
out-of-scope changes.

Out of scope: V1 installer/template parity, new evidence classes, self-
governance cutover, release publication, and unrelated capability additions.

Unknown: whether future committed Work Item changes need a separate base-diff

introduce that provider.

## Acceptance Criteria

1. A red scope or freshness decision cannot finish, archive, or close.
2. A scope-authorized working-tree change after `start` is not classified as a
   stale Contract solely because the current snapshot differs from the start
   snapshot.
3. Verification evidence records the snapshot observed after the verification
   command completes.
4. CLI and MCP use the same corrected evidence and lifecycle semantics.
5. Existing conformance, lifecycle, security, and performance tests remain
   passing.
