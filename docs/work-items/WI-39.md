# WI-39 — Explicit Agent Discovery / Adapter Layer

## Intent and Goal

Introduce an explicit, verifiable, and reversible Agent Discovery / Adapter
layer without introducing governance decisions. Runtime installation,
repository attachment, discovery, connection, and compliance remain separate
states.

## Scope and Out of Scope

In scope: a provider-neutral adapter contract; canonical manifest/version
handling; provider detection and explicit install plans; repository-local
ownership records; fail-closed doctor/repair/detach behavior; standard states
and exit codes; CLI-first operation; and synchronized English, Chinese, and
Japanese documentation.

Out of scope: automatic provider injection during `attach`, global MCP or home
directory configuration, Agent prompts as governance authority, automatic
Work Item decisions, public Release/Homebrew changes, and a `--force` detach
shortcut.

## Hard Constraints

- Every operation requires explicit `--repo`; no Core-global current project.
- `attach` remains Layer 2 and never modifies Agent-host files.
- `.ai/agent-interface.json` contains discovery facts only; unknown fields and
  incompatible versions fail closed.
- `agent install` is the only normal write entry point for an adapter.
- Managed content is owned by a repository-local digest record and preserves
  unrelated user content.
- Modified or ambiguous managed sections make `detach`/`repair` refuse safely.
- CLI talks directly to Core; MCP is optional and never a prerequisite.

## Acceptance Criteria

1. `agent list`, `install`, `doctor`, `repair`, and `detach` all require and
   honor explicit repository context.
2. A/B repositories can be operated in parallel without sharing identity,
   manifest, adapter ownership, or state.
3. Detection is read-only; `attach` and `--provider auto` do not write Agent
   host/global files.
4. Explicit installation is idempotent, preserves unrelated bytes, and writes
   a strict `.ai/adapters/<provider>.json` ownership record.
5. Duplicate markers, repository mismatch, symlink/reparse targets, malformed
   sections, and changed managed content fail closed.
6. `agent doctor --json` derives the documented state machine and standard exit
   code; `VERIFIED` requires a repository-bound probe with matching ID.
7. CLI remains fully usable when MCP is unavailable, and no global MCP config
   is changed.
8. English, Chinese, and Japanese docs distinguish discovery, installation,
   connection, verification, and compliance.
9. Existing format, Clippy, package, Windows runtime, and V1 Oracle gates
   remain green.

## Required Evidence

Protocol/manifest tests; provider detection and ownership tests; A/B isolation;
managed-section idempotency and preservation; conflict/detach fail-closed
tests; doctor state/exit-code tests; CLI-without-MCP test; no-global-write
tests; trilingual documentation parity; and full hosted quality, Windows
runtime, and V1 Oracle receipts.
