# WI-35 — First Public Release and Homebrew Tap Bootstrap

## 意図と目標

local configuration-complete の WI-34 candidate から最初の external hosted release を実行します。正確な immutable
GitHub Release を publish し、identity-bound pull request で protected Homebrew tap を bootstrap し、runtime semantics
を変更せず real installation receipt を記録します。この repository に V1 は install しません。

## Scope と Out of Scope

Scope は、明示的な hosted workflow dispatch または tag 実行、承認済み source commit 上の immutable `v0.1.0` tag、
hosted source/target build/manifest/archive/SBOM/smoke/provenance receipt、GitHub Release publication、
`xinglun/homebrew-tap` の作成と protection、正確な `homebrew-handoff.json` の検証、identity-bound Formula pull request、
Homebrew install/test/uninstall、public archive install receipt、final release state report です。

Out of Scope は Rust governance semantics の変更、`cockpit.toml` の JSON 化、V1 install、tap default branch への direct write、
`curl | sh`、Linuxbrew、crates.io publication、広い ABI claim、この development checkout の repository attach、
external-write authorization なしの release action です。

## Sources と Unknowns

Sources は accepted WI-34 と三言語 design/plan、正確な release workflow と `cockpit-release` validator、GitHub hosted-runner/
artifact-attestation docs、Homebrew tap/Formula guidance、protected tap repository policy、WI-34 post-publication handoff contract です。

WI-34 が local candidate、workflow policy、strict manifest/Formula/handoff type、Cargo Git fixture、V1 Oracle、local quality gate を
証明済みであることは Known です。現在の remote に public `v0.1.0` tag、provider Release、`xinglun/homebrew-tap` はありません。

Tap ownership/branch protection、GitHub App または narrow credential、hosted runner result、provider Release identity、attestation ID、
real adopter installation result は、external state が変わるまで execution を block する Unknowns です。

## Acceptance Criteria

1. Human-authorized hosted run が archived WI-34 commit に bind され、tag event は新しい immutable `v0.1.0` reservation である。
   moved/reused tag は fail closed。
2. Source-quality、release-policy、5 target build、archive/member、manifest/checksum、Homebrew/Linux/Windows smoke、final candidate
   attestation が同じ run で pass する。
3. Provider Release には allowlist 済みの manifest、checksum、Formula、5 archive、5 SBOM だけがあり、各 artifact が canonical
   manifest と attestation subject に一致する。
4. Provider Release identity、tag target、workflow commit、lockfile digest、binary version、provider Release ID を記録して独立検証する。
5. `xinglun/homebrew-tap` の `main` が protected で、正確な Formula handoff が review 可能な PR を開く。default branch へ direct push しない。
6. named source run から handoff を取得し attestation/expiry を検証する。destination、commit、manifest digest、Formula digest、
   provider Release ID、action が PR と一致する。
7. supported macOS ARM64/Intel host で Homebrew install、`brew test`、`ai-cockpit --version`、uninstall、link removal の receipt を記録し、
   Linux/Windows runner で archive checksum、extract、`--version`、`--help` の receipt を記録する。
8. Second public version が存在する場合、rollback receipt は immutable prior Release を指定する。それまでは first-release rollback procedure
   だけを記録し、upgrade result を捏造しない。
9. Development repository に `.ai/` を作らず、V1 を install せず、publication で runtime code や configuration format を変更しない。

## Required Evidence

Hosted run ID/commit binding、tag/ref event payload、source-quality/smoke conclusion、release manifest、`SHA256SUMS`、SBOM、archive digest、
attestation ID、provider Release URL/ID/asset inventory、protected tap settings、signed/attested `homebrew-handoff.json`、Formula PR URL/diff/
merge commit、macOS Homebrew install/test/uninstall receipt、Linux/Windows archive receipt、second version 後の rollback/upgrade receipt、
two independent reviewers、skip/failure した external step の明示記録が必要です。WI-34 local evidence は参照しますが hosted evidence に書き換えません。
