`examples/csharp/README.md`. It compares that page section by section and
preserves applicable governance meaning for a .NET repository. It is not a
second Contract schema, a .NET toolchain guarantee, or a second-technology
adopter acceptance receipt.

## Install and attach without copying the source installer

Installation is a Runtime boundary, not a project template operation. Select an
immutable public Release, verify its archive and binary SHA-256, and install
the binary once outside the repository. Then bind each repository explicitly:

```bash
repo=/path/to/csharp-repository
ai-cockpit --version
ai-cockpit inspect --repo "$repo"
ai-cockpit attach --repo "$repo"
ai-cockpit status --repo "$repo"
ai-cockpit doctor --repo "$repo"
```

Review the detected project facts before confirming a profile. Agent adapter
installation is a separate, explicit repository action; it does not modify
global Agent or MCP configuration. See [Install AI Cockpit](../getting-started/installation.md),
[Adopter configuration](../getting-started/adopter-configuration.md), and
[Installed Runtime lifecycle](installed-lifecycle.md).

The reference variables `AI_COCKPIT_TEMPLATE_REF` and
`AI_COCKPIT_TEMPLATE_RAW_BASE`, its `curl`-downloaded `install.sh`, and flags
`--stack csharp --update-makefile --create-adoption` are therefore not copied.
They describe the source installer's workflow, while the Rust route keeps
Runtime delivery, repository scaffold, project policy, and Agent discovery as
independently reviewable boundaries.

## C# verification as adopter-owned evidence

The following commands are examples of project facts, not commands shipped by
the Runtime:

```bash
dotnet format --verify-no-changes
dotnet test
dotnet build -warnas-error
```

After a human-owned Contract is ready, bind a fresh result with the installed
Runtime. For example:

```bash
ai-cockpit verify --repo "$repo" --work-item WI-csharp-change \
  --command dotnet --args test
```

Additional checks can be declared as separate verification entries. A
repository's proportional `light`, `standard`, or `strict` profile decides
which checks are required; a stronger Verification Tier is not Evidence
Assurance. Hosted CI, provider attestations, and enterprise controls remain
delegated evidence.

The source coverage suggestion (`src/**` for production and
`tests/**` or `**/*Tests/**` for tests) is a policy idea, not a mandatory file
layout. Use repository-relative Contract boundaries and the current
scope-overlap validator. Unknown or unsafe patterns remain fail-closed rather
than being silently treated as disjoint.

## Current Contract mapping

Start with a not-ready skeleton so facts and decisions stay separate:

```bash
ai-cockpit work-item new --repo "$repo" --id csharp-change --mode code
```

The human owner must then define intent, goal, scope, out-of-scope, acceptance,
authority, and any required evidence before `preflight` can become actionable.
The current Rust fields map the source ideas as follows:

- `protocolVersion` and optional `contractVersion` identify the Rust protocol;
  source `contractVersion: 2` is not a direct wire contract.
- `workItemId`, `mode`, `scope`, and `guidelines` retain their governance
  meaning with repository-relative safety validation.
- `verification` contains descriptive typed checks. It never replaces fresh
  execution or grants permission. Strict/release `checkpointPolicy` supplies
  the current Agent Risk floor; source `ai*` names are not copied as a second
  registry.
- `acceptanceCriteria`, numbered acceptance evidence, and `intentAlignment`
  preserve observable completion without inventing a guideline result.
- `authority` is a repository-local declaration. Human identity, provider
  approval, and enterprise assurance remain external evidence.

## Inheritance and non-claims

An attached C# repository inherits the same reader-facing workflow, stop
states, Outcome rules, and evidence boundaries from the shared Runtime through
its own `.ai/` and Agent adapter. Its repository identity, Contract, snapshot,
Work Items, and evidence remain isolated by explicit `--repo`.

This page intentionally does not copy `install.sh`, `Makefile.ai.stack`, source
Python checks, source guard YAML, or the source JSON examples. It also does not
claim that this Rust repository has executed a C# adopter acceptance. A future
multi-technology acceptance must be a separate, explicitly evidenced batch.

[Reference parity](reference-parity.md) records this as semantic/documentation
parity rather than source command or JSON-wire compatibility.
