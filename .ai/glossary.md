# AI Cockpit glossary

- **Runtime** — the externally installed shared `ai-cockpit` executable. It
  has no global current repository or Work Item.
- **Repository Context** — one request-scoped repository binding resolved from
  an explicit `--repo` path and repository-owned Protocol state.
- **Repository Protocol** — the repository-local storage and identity contract
  under `.ai/`; it is not a copy of the Rust Runtime.
- **Agent Discovery / Adapter** — an explicit, owned, reversible provider
  integration that helps an Agent find the repository interface. It is not
  governance policy and does not prove compliance. New Cursor adapters use the
  provider-native `.cursor/rules/ai-cockpit.mdc` surface; existing managed
  `.md` adapters remain readable and reversible.
- **Work Item** — one bounded change with a human-owned Contract, evidence,
  human decision, and lifecycle records.
- **Contract** — the Work Item declaration of intent, goal, scope, out-of-scope
  boundaries, authority, acceptance, sources, verification, and required
  evidence. The Runtime validates it but does not invent human decisions.
- **Intent** — the human-owned reason for the change. When supplied, it may
  describe the problem, constraints, rationale, and intended user benefit;
  missing intent remains unknown rather than being inferred.
- **Summary** — the Runtime-bound delivery record describing changed paths and
  reasons, sources, verification commands/results, guideline compliance,
  unknowns, risk, generated or destructive changes, and observed issues.
- **Preflight Review** — the pre-edit Contract and snapshot review. `not_ready`
  or `needs_human_confirmation` is a mandatory human pause; a successful
  command or yellow result is not authorization.
- **Pause Rule** — when required facts, authority, scope, evidence, or a
  human decision are missing or contradictory, stop and show the reason,
  options, recommendation, and resume condition.
- **Scenario Coverage** — explicit normal, edge, failure, and recovery cases
  required by a high-risk Contract. The Runtime verifies declared coverage; it
  never manufactures evidence for an untested scenario.
- **Human Decision** — a structured, auditable decision containing the actor,
  authority source, reason, evidence and policy references, timestamp, and
  resume condition. Approval requirements are policy-defined, not hard-coded.
- **Evidence Governance** — the identity, freshness, provenance, scope, and
  retention rules that bind a fact to a repository, Work Item, snapshot, and
  Runtime. Invalid or contradictory evidence fails closed.
- **Native Governance Evidence** — evidence generated by the Runtime itself,
  such as Contract, snapshot, verification, archive, and decision records.
- **Delegated Domain Evidence** — evidence produced by an external provider,
  such as hosted CI, attestations, SBOM, or enterprise approval. AI Cockpit
  can require, bind, validate, display, and archive it, but does not forge it.
- **Snapshot** — an observed repository state used to bind decisions and
  evidence.
- **Receipt** — content-bound verification evidence that may be reused only
  when all authorized identity bindings still match.
- **Outcome** — the visible human handoff summarizing facts, unknowns,
  evidence, decision, and next action with 🟢/🟡/🔴. A raw machine JSON record
  is not a substitute for this presentation.
- **Green / Yellow / Red** — proceed with sufficient evidence / investigate or
  obtain confirmation / stop because a required control failed.
- **Runtime-only upgrade** — a compatible executable change that does not
  modify repository-owned `.ai/` state.
- **Repository migration** — an explicit, reviewed, versioned change to
  repository Protocol or configuration state; it never rewrites historical
  Work Items or evidence.
